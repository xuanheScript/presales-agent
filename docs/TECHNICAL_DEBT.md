## P1：全文需求理解与有界角色工时估算（第四期已完成）

### 已完成：`full_document_discovery_v1`

- 正式需求基线先执行字符数与估算 Token 容量预检；超出模型可用输入容量时直接失败，不截断、不切片、也不自动降级。
- 使用一次 `Output.object()` 调用同时生成项目分析和完整功能目录，最多返回 500 个功能；输出 Schema 严格拒绝未知字段。
- 已完全移除方案与成本分析链路中的段落、块、引文、offset、hash、source ID、evidence ID 和 evidence lineage。
- 功能按 NFKC 规范化后的模块名与功能名确定性归并，保留更完整的描述、更高复杂度和稳定去重后的直接依赖。
- 全文发现结果作为唯一 `full_document_discovery/global` 工作单元持久化；Trigger 重试复用成功 artifact，不重复发送全文。
- 发现阶段保留 execution/work-unit 租约、心跳、generation fencing、幂等输出哈希以及模型调用 Token、延迟和 finish reason 账本。
- 全文发现完成后生成角色目录和额外工作，再将结构化功能列表有界分批执行角色工时估算；成本仍由确定性规则计算。
- 最终估算快照不再保存证据字段，并继续原子提交不可变估算版本。
- AI SDK telemetry 默认不记录客户需求和模型输出，只上报协议版本、ID、数量、长度、容量和状态。
