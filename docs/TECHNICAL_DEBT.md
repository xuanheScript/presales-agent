## P1：Breakdown 有界分批结构化输出（第三期已完成）

### 已完成：`batched_structured_v2`

- 已移除主路径 CSV 功能发现，需求按 Markdown 业务块和语义边界确定性切片；列表、表格和 fenced code block 作为受保护块，不在块内拆分。
- 每片受字符数和估算 token 双上限约束：目标 3600 字符/2400 token，最大 4500 字符/3000 token，最多 12 片；不可安全拆分的超大 Markdown 块和超片数需求直接 fail-close。
- 每个焦点片段按需求 ID、规范化焦点内容和同内容出现序号生成稳定 `SRC-*`；同时保留原始需求绝对 offset，重叠上下文不会改变焦点身份。
- 每片使用独立小型 `Output.object()` 结构化发现功能，最多 12 个；通过 `functions` / `no_functions` 显式确认每个 `SRC-*` 的覆盖状态。
- 每个功能必须提供至少 4 个字符、可在当前焦点原文中连续精确查找的 `evidenceQuote`；重叠上下文只用于理解边界，不能作为当前片功能证据。
- 分片调用串行共享既有功能命名目录，要求同一业务功能复用模块名和功能名；应用侧再按 NFKC 规范化后的模块名和功能名确定性归并，并按来源顺序保留稳定顺序。
- 归并完成后才生成稳定 `FUN-*`，再沿用第二期角色目录、额外工作和分批角色工时链路；数据库快照和成本公式保持不变。
- 参考检索、需求切片、所有分片发现、角色目录、额外工作及工时批次现在共享同一个 Breakdown 节点级 90 秒 deadline 和取消信号。
- AI SDK telemetry 已默认关闭 input/output 记录，仅上报协议版本、ID、数量、长度、批次和状态，避免客户需求与模型结果进入 Trace。
- 已增加纯函数测试，覆盖稳定 `SRC-*`、原始 offset、语义切片、Markdown 块保护、切片数量上限、来源覆盖、焦点证据、`no_functions`、跨片归并和非法 Schema。
